Проєкт Simple OTP — це десктопний додаток для генерації TOTP-кодів (Time-based One-Time Passwords) з GUI на основі wxPython. Проєкт має чітку архітектуру, добре документований і використовує сучасні практики розробки. Однак, з точки зору безпеки, варто звернути увагу на кілька ключових аспектів — як сильних, так і потенційно вразливих. 
 
✅ Сильні сторони з точки зору безпеки 
1. Шифрування секретів 

    Всі TOTP-секрети шифруються перед зберіганням у файлі accounts.json.
    Використовується AES-256-GCM — сучасний, безпечний режим шифрування з аутентифікацією.
    Ключ для шифрування похідний від пароля користувача за допомогою PBKDF2-HMAC-SHA256 з 600 000 ітерацій, що відповідає рекомендаціям OWASP (станом на 2023–2025 роки).
    Для кожного акаунту генерується унікальна криптографічна сіль (salt) через secrets.token_bytes(16).
     

2. Цілісність та конфіденційність 

    AES-GCM забезпечує і конфіденційність, і цілісність даних (через аутентифікаційний тег).
    При спробі розшифрувати з неправильним паролем викидається InvalidTag — це запобігає частковому розшифруванню або підбору.
     

3. Управління паролями 

    Пароль не зберігається на диску — лише в пам’яті під час сесії.
    При запуску відбувається автентифікація через розшифрування першого акаунту.
    Максимум 3 спроби входу, після чого додаток завершується — це обмежує brute-force атаки.
     

4. Відсутність plaintext-секретів 

    Секрети ніколи не зберігаються у відкритому вигляді.
    Навіть у тестовому акаунті (authenticationtest.com) використовується шифрований секрет.
     

5. Оновлення безпеки 

    Параметри шифрування (зокрема, кількість ітерацій PBKDF2) винесені в проєктову константу, що дозволяє легко оновлювати їх у майбутньому.
     

 
⚠️ Потенційні ризики та рекомендації 
1. Зберігання пароля в пам’яті 

    Пароль зберігається в пам’яті (MainWindow.password) протягом усієї сесії.
    У Python немає гарантій, що пам’ять буде негайно очищена (особливо через garbage collector).
    Рекомендація: 
        Використовувати bytearray замість str для паролів (щоб можна було явно очистити).
        Додати можливість "блокування" додатку (наприклад, через таймер бездіяльності), після чого пароль очищається.
         
     

2. Файл налаштувань settings.json зберігається поруч із кодом 

    settings.json створюється в каталозі проєкту, а не в ~/.config/ або %APPDATA%.
    Це може призвести до:
        Випадкового коміту налаштувань у Git (хоча .gitignore це запобігає).
        Проблем з правами доступу на мультикористувацьких системах.
         
    Рекомендація: 
        Використовувати platformdirs або appdirs для зберігання даних у стандартному місці (%APPDATA%\Simple OTP\ на Windows).
         
     

3. Відсутність захисту від скріншотів/логгерів 

    TOTP-коди відображаються у вікні, яке не захищене від:
        Знімків екрана
        Клавіатурних логгерів (при введенні пароля)
        Accessibility API (наприклад, зловмисні скрін-ридери)
         
    Рекомендація:
        На Windows можна використовувати SetWindowDisplayAffinity для запобігання скріншотам (через ctypes).
        Для пароля — використовувати wx.TextCtrl з TE_PASSWORD, але це лише приховує символи, не запобігає логуванню.
         
     

4. Буфер обміну (clipboard) 

    При копіюванні TOTP-коду він залишається в буфері обміну довільно довго.
    Це може призвести до витоку, якщо інша програма читає буфер.
    Рекомендація:
        Додати опцію очищення буфера через N секунд (вже є в settings.json як clipboard_timeout, але не реалізовано).
        Використовувати безпечніший спосіб передачі коду (наприклад, автозаповнення у веб-форми через розширення — але це виходить за межі додатку).
         
     

5. Відсутність верифікації цілісності файлу accounts.json 

    Файл можна модифікувати ззовні (наприклад, видалити акаунти або підмінити зашифровані дані).
    Хоча це не дасть зловмиснику отримати секрет, це може призвести до DoS (пошкодження файлу → помилка завантаження).
    Рекомендація:
        Додати MAC (Message Authentication Code) для всього файлу або кожного акаунту.
        Або зберігати хеш-суму файлу і перевіряти її при завантаженні.
         
     

6. Глобальний екземпляр audio_player 

    Не є прямою безпековою проблемою, але глобальний стан ускладнює тестування і може призвести до непередбачуваної поведінки.
    Рекомендація: використовувати dependency injection замість глобального об’єкта.
     

 
🔒 Висновок 
Проєкт Simple OTP реалізований з високим рівнем безпеки для додатку цього класу: 
    Використовується сучасна криптографія.
    Паролі та секрети ніколи не зберігаються у відкритому вигляді.
    Реалізовано базові заходи проти brute-force.
Проте, для використання в високоризикових середовищах (наприклад, для корпоративного або фінансового доступу) рекомендується: 
    Додати очищення пароля з пам’яті після таймауту.
    Реалізувати очищення буфера обміну.
    Зберігати файли у стандартному каталозі користувача, а не в каталозі проєкту.
    Додати захист від скріншотів (на Windows).
    Розглянути можливість автоматичного блокування при бездіяльності.
