1. Зберігання пароля в пам’яті 

    Пароль зберігається в пам’яті (MainWindow.password) протягом усієї сесії.
    У Python немає гарантій, що пам’ять буде негайно очищена (особливо через garbage collector).
    Рекомендація: 
        Використовувати bytearray замість str для паролів (щоб можна було явно очистити).
        Додати можливість "блокування" додатку (наприклад, через таймер бездіяльності), після чого пароль очищається.
         
     

         
     

3. Відсутність захисту від скріншотів/логгерів 

    TOTP-коди відображаються у вікні, яке не захищене від:
        Знімків екрана
        Клавіатурних логгерів (при введенні пароля)
        Accessibility API (наприклад, зловмисні скрін-ридери)
         
    Рекомендація:
        На Windows можна використовувати SetWindowDisplayAffinity для запобігання скріншотам (через ctypes).
        Для пароля — використовувати wx.TextCtrl з TE_PASSWORD, але це лише приховує символи, не запобігає логуванню.
         
     

4. Буфер обміну (clipboard) 

    При копіюванні TOTP-коду він залишається в буфері обміну довільно довго.
    Це може призвести до витоку, якщо інша програма читає буфер.
    Рекомендація:
        Додати опцію очищення буфера через N секунд (вже є в settings.json як clipboard_timeout, але не реалізовано).
        Використовувати безпечніший спосіб передачі коду (наприклад, автозаповнення у веб-форми через розширення — але це виходить за межі додатку).

5. Відсутність верифікації цілісності файлу accounts.json 

    Файл можна модифікувати ззовні (наприклад, видалити акаунти або підмінити зашифровані дані).
    Хоча це не дасть зловмиснику отримати секрет, це може призвести до DoS (пошкодження файлу → помилка завантаження).
    Рекомендація:
        Додати MAC (Message Authentication Code) для всього файлу або кожного акаунту.
        Або зберігати хеш-суму файлу і перевіряти її при завантаженні.
